# Super-LIO OctVox 地图代表点更新策略消融实验

## 一、实验目的

验证当前 Super-LIO OctVox 地图的增量平均策略，是否会造成局部几何信息损失、表面模糊或错误的几何约束，以及改为保留真实观测点能否改善地图质量和 LIO 定位表现。

重点验证一个新策略：

**每个子体素始终保留距离该子体素几何中心最近的真实观测点，不对坐标进行增量平均。**

本实验不预设新策略一定更好。需要通过控制变量实验判断：

1. 增量平均是否确实造成了地图几何损失；
2. 保留真实观测点能否减少虚假几何位置；
3. 中心最近点策略是否比首次观测点策略更稳定；
4. 地图几何改善能否进一步转化为 LIO 定位表现改善；
5. 新策略是否带来额外计算、内存或实时性成本。

## 二、实验基本原则

1. 使用同一份原始数据，不使用历史 sl/e1 两个独立 bag 做交叉对照。
2. 所有实验必须使用相同的原始 LiDAR 数据、IMU 数据、时间戳、逐点去畸变结果和点云预处理配置。
3. 离线地图几何实验必须固定同一份位姿轨迹，避免地图策略与位姿变化相互影响。
4. 进入地图更新模块的点必须完全一致，不能因为不同策略而改变输入点集或下采样方式。
5. 第一阶段不修改滤波器、ESKF、匹配损失函数、KNN 查询、体素划分及其他算法逻辑，只改变地图代表点的更新方式。
6. 暂时不进行彩色点云实验，不使用椒盐率推断几何精度。
7. 没有独立真实轨迹时，只能得出相对几何一致性和定位稳定性结论，不得宣称绝对定位精度提高。

## 三、实验前源码审计

先检查当前 Super-LIO 使用的 OctVox 实际实现，不要直接依据论文推断代码行为。

需要确认：

1. 父体素尺寸、八个子体素的实际边界和中心计算方式。
2. 每个子体素当前是否最多保存一个代表点。
3. 当前增量平均的准确公式、计数器更新及计数上限。
4. 新点与已有代表点合并时的距离阈值、拒绝条件和更新条件。
5. 当前地图是否还存在其他代表点替换、滤波或裁剪机制。
6. OctVox 的地图点是否直接参与 HKNN / KNN 查询和点到面匹配。
7. 当前扫描进入 OctVox 前是否已经进行 center-based downsampling。
8. 当前地图更新是否存在多线程竞争、异步更新或点顺序依赖。

输出 `OCTVox_UPDATE_AUDIT.md`，包含实际源码路径、函数名称、关键代码位置和现有更新流程。

**注意：** 不要把扫描预处理阶段的 center-based downsampling 与 OctVox 跨帧增量平均混为一谈。本实验只修改后者。

## 四、实验分组

所有组保持相同的父体素、八子体素结构、空间索引、合并门槛和地图查询方式。

### A组：当前增量平均（Baseline）

保持现有 OctVox 实现完全不变。

新观测点满足原有合并条件后，按照当前计数器和均值公式更新代表点。

作为对照基线。

### B组：首次观测点保留（First Observation）

每个子体素首次被占据时，保存第一个真实观测点。

之后的观测仍按原有合并条件判断，但不再改变代表点的 XYZ。

观测计数器仍按原有逻辑更新，以便统计和比较。

本组用于判断：仅取消增量平均，是否就能改善几何保真度。

### C组：距离子体素中心最近的真实点（Nearest-to-Center）

这是本次重点实验组。

对每个子体素，预先计算固定几何中心：

\[
c_s=(x_c,y_c,z_c)
\]

第一次有点进入时，保存该真实观测点。

后续新观测点满足原有合并条件后，计算：

\[
d_{\mathrm{new}}=\|p_{\mathrm{new}}-c_s\|^2
\]

\[
d_{\mathrm{old}}=\|p_{\mathrm{old}}-c_s\|^2
\]

只有当：

\[
d_{\mathrm{new}}+\epsilon<d_{\mathrm{old}}
\]

才用新观测点替换原代表点。

其中：

- 所有距离均在地图统一坐标系下计算。
- 必须使用当前子体素的几何中心，不是父体素中心。
- 代表点必须来自真实 LiDAR 测量，不得生成平均坐标。
- 不对 XYZ 做任何平均。
- 原有合并条件、距离阈值和子体素占用规则保持不变。
- `epsilon` 用于避免浮点误差引起无意义的重复替换，应在实验前固定并记录。
- 计数器继续记录观测次数，但不参与代表点坐标计算。
- 输出每个子体素的最终代表点来源帧和中心距离，便于追溯。

额外要求：

每帧、每个子体素如果存在多个候选点，先从该帧的候选点中选出距离子体素中心最近的一个，再参与地图更新，避免高密度扫描帧仅因点数更多而获得更多更新机会。

但必须先确认原有合并条件的具体语义。如果原有合并门槛依赖当前代表点，不能擅自删除或替换，应单独记录这种依赖以及它可能产生的顺序效应。

### D组：全量真实观测点累积（Raw Accumulation，可选）

作为性能和几何参考组。

在每个子体素中保存全部符合原有插入条件的真实观测点，不计算均值，也不执行代表点替换。

本组主要用于评估：
- 原始观测空间分布；
- 重复观测造成的密度偏置；
- KNN 搜索成本；
- 内存和实时性开销。

如果全量点导致计算量过大，可以先在离线建图实验中实施，不必立即接入飞行版本。

## 五、阶段一：固定轨迹的离线地图几何实验

这是本实验最重要的部分。

### 5.1 数据输入

使用同一份 Retail_Street 原始 bag 重放结果。

统一使用：
- 同一批原始 LiDAR 扫描；
- 同一批 IMU；
- 同一条固定 Odom；
- 同一批已去畸变的 body-frame 点云；
- 同一时间窗口；
- 同一帧采样方式；
- 同一空间范围；
- 同一预处理、下采样和有效点过滤逻辑。

必须在进入地图更新模块之前，保存实际输入地图的点集及对应帧时间戳。

A/B/C/D 组必须逐帧使用完全相同的输入点，不允许不同组重新运行 LIO 生成不同的输入点云或轨迹。

建议先采用历史 sl 对应的重放窗口，并优先完成重放复现性检查。

### 5.2 地图构建

分别构建 A/B/C 地图，D 组视计算条件选做。

保持：
- 完全相同的地图空间范围；
- 完全相同的父体素及子体素尺寸；
- 完全相同的地图更新顺序；
- 完全相同的初始状态；
- 完全相同的输入扫描及输入点集。

每组记录：

- 地图最终点数；
- 父体素数量；
- 已占用子体素数量；
- 每个子体素的观测次数分布；
- 每个代表点的来源帧；
- 每个代表点到子体素中心的距离；
- 更新次数和实际替换次数；
- 地图建立耗时；
- 内存占用。

### 5.3 几何评价指标

不要再使用之前的 25cm 体素 consistency_cost 作为核心几何指标。

重点使用以下指标：

**指标一：局部平面厚度**

在稳定平面区域提取局部点集，拟合平面：

\[
n^Tx+d=0
\]

计算点到平面的绝对距离：

\[
r_i=|n^Tx_i+d|
\]

报告 P50、P90、P95 和 RMS。

统计时剔除不满足平面拟合条件的区域，不能把墙角、曲面或多个物体表面混入同一平面统计。

**指标二：留出帧点到面残差**

使用部分扫描建立地图，选择另一组扫描作为测试帧。

测试帧及其邻近时间窗口必须完全排除在参考地图之外，不能使用普通的单帧 LOO 代替时间隔离。

测试时保持测试帧原始固定 Odom，不进行位姿优化，计算其点到参考地图局部平面的距离。

报告：
- 残差 P50/P90/P95；
- RMS；
- 有效匹配点比例；
- 不同时间段及空间区域的残差。

至少进行一种邻近帧排除时间窗的敏感性检查，并记录具体排除范围。

**指标三：结构边缘保真度**

选择墙角、立柱、门框等稳定结构。

比较：
- 边缘扩散宽度；
- 边缘位置偏移；
- 是否出现虚假中间点；
- 是否出现双层边缘或局部缺口。

必要时对不同组使用相同的空间截面和相同的统计脚本。

**指标四：表面重合情况**

在相同的留出扫描上，分别检查多个时间段观测的表面是否重合。

不要只看最终融合地图的视觉效果。应保留逐帧观测来源，检查不同帧点云在同一结构上的空间分布。

### 5.4 特别检查：中心最近点是否产生空间选择偏差

C 组虽然保留真实点，但选择规则本身会使代表点倾向于子体素中心。

必须额外统计：

- 被选代表点到子体素中心的距离分布；
- 被选代表点到局部拟合平面的有符号距离；
- 不同平面法向下的偏移情况；
- C 相对 B 的边缘位置变化。

重点判断：C 是否只是让点更接近子体素中心，却导致实际物理表面产生系统性偏移。

不能简单把中心距离变小解释成几何精度提高。

## 六、阶段二：完整 LIO 闭环实验

第一阶段完成后，再考虑把 B/C 策略接入完整 Super-LIO。

A/B/C 分别使用独立运行实例，从同一原始 bag、同一初始状态和同一参数配置重新开始。

除地图代表点更新方式外，不修改：
- IMU 处理；
- 逐点去畸变；
- ESKF；
- scan-to-map 残差；
- KNN / HKNN；
- 特征筛选；
- 其他滤波和状态更新参数。

记录：

1. Odom 轨迹及逐时刻姿态变化。
2. 路径长度和局部轨迹变化。
3. 点到面残差分布。
4. 每帧有效匹配数量。
5. 匹配邻居的空间分布及来源帧分布。
6. ESKF 状态更新量、创新量和异常更新情况。
7. 不同空间区域的定位稳定性。
8. CPU、内存、单帧处理耗时和丢帧情况。

特别注意：

- 残差下降不等于绝对定位精度提高。
- 轨迹更平滑不等于轨迹更准确。
- 地图更规整不等于定位一定更准确。
- 无独立 GT 时，必须把结论限制在相对一致性和系统稳定性层面。

如果完整闭环出现差异，需要结合阶段一结果分析差异是由地图几何改善产生，还是由 KNN 邻居变化、观测权重变化等因素产生。

## 七、额外控制实验

### 7.1 帧顺序敏感性

A/B/C 都按照相同时间顺序建图。

另外对 B/C 至少做一次反向或随机顺序建图，观察最终地图差异。

特别关注 C 组：如果合并门槛依赖当前代表点，连续替换可能产生顺序依赖。中心最近点策略应尽量具备可重复的结果。

报告相同输入点集不同输入顺序下的：
- 代表点变化比例；
- 地图几何指标变化；
- 不同子体素的最终选择差异。

### 7.2 多次扫描密度影响

统计不同扫描帧进入每个子体素的有效候选数量。

分析 C 组的代表点选择是否被高密度帧主导。

验证逐帧候选点预选机制是否能够减少扫描密度差异带来的选择偏置。
