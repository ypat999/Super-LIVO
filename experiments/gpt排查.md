这次核实基本推翻了我上一轮对当前工作区的优先级判断。20k 截断应从当前楼梯间实验的排查清单中移除：它在源码中确实存在，但现有数据没有触发，不能再把它当成 voxel 缩小后精度变化的主要嫌疑。

我建议调整顺序：先修复并验证 `KNNHeap<8>` 的最远元素定位，再补跑 `voxel=0.10`。 这里有一个重要原因：如果 K=8 时堆的更新逻辑确实只检查前 5 个槽位，那么此前 voxel=0.15 的结果是在一个可能错误的邻域选择器下得到的。它可以说明当前实现下指标改善，却不能保证修复 KNN 后趋势仍然成立。

具体建议如下：

### 1. 先修 KNNHeap，不要只改一处比较逻辑就直接跑实验

如果 `update_worst_unrolled()` 在 `K=8` 时确实只检查 `dist2_[0..4]`，那么它找到的不是 8 个候选中的最远点，而只是前 5 个槽位中的最远点。这会导致第 6～8 个槽位里的较远候选无法被正确淘汰，最终返回的邻居集合可能不是全局最近的 8 个点。

建议将最远元素定位改成遍历模板参数 `K` 的通用实现：

```
worst_idx = 0;
for (int i = 1; i < K; ++i) {
    if (dist2_[i] > dist2_[worst_idx]) {
        worst_idx = i;
    }
}
```

这只是示意代码，实际修改要保留原有的堆未填满、插入和距离相等时的处理语义。同时全局搜索 `KNNHeap`，检查是否还有其他假设 `K=5` 的固定索引或展开逻辑。

### 2. 修复后先做单元测试

这比直接跑楼梯间 bag 更重要。建议构造随机点集和随机插入顺序，将 `KNNHeap<8>` 的结果与暴力计算全部距离后排序得到的精确 Top-8 对比。

重点覆盖：

- 候选数量少于、等于和大于 8。
- 第 6～8 个槽位存在明显较远点，后续又插入更近点。
- 随机插入顺序、多组随机数据。
- 距离相等或非常接近的情况。
- 同样测试 `KNNHeap<5>`，避免修复 K=8 时破坏原有行为。

测试的判据不是条件数或残差，而是返回的邻居集合与暴力 Top-K 是否完全一致。

### 3. 再跑三组，而不是只补 0.10

建议实验顺序

| 实验 | voxel | 目的              |
| -- | ----- | --------------- |
| A  | 0.25  | 修复后的基准          |
| B  | 0.15  | 确认此前观察到的改善是否仍存在 |
| C  | 0.10  | 检查进一步细化的效果      |

三组都使用修复后的同一份代码，固定 K=8 和其余参数。原因是此前 0.25→0.15 的趋势可能受到 KNN 邻域选择错误影响；直接拿旧 0.15 和新 0.10 对比，会把代码修复和 voxel 变化混在一起。

主要看 1F 的 `dxy/dyaw`、跨帧墙面法向偏移，以及有效平面约束数量和 KNN 邻居数量分布。`cond(Yk)` 和拟合残差可以保留，但它们是局部优化质量指标，不应替代几何精度指标。

最终判断：先修 KNNHeap，再复跑 0.25、0.15、0.10。 这是比继续扩展 voxel 参数组合更有价值的下一步。20k 截断只是在楼梯间数据上排除了，Retail_Street 仍应在实际运行时检查点数和截断日志，不能把两个数据集混为一谈。
