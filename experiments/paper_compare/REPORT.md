# 四臂论文级对比（move / retail / room / ntu03 / ntu01 / rtk）

> 生成脚本 `experiments/scripts/paper_matrix/paper_eval.py`；原始表 `metrics.csv`，图在 `figs/`。

## 0. 口径

- 四臂：**FL2** = 官方 FAST-LIVO2；**SL** = 官方 Super-LIO（rtk/room 用自带视觉配置，其余数据集 LIO-only）；**A** = Super-LIO 主干 + 轻量视觉；**B** = Super-LIO 主干 + 紧耦合视觉。
- 统一 1× 实时播放、同一 FastDDS / ROS_DOMAIN_ID、同一外部探针；延时为「odom 到达 − 对应雷达帧到达」的 algo 项。
- 结果根：**B 取 `paper_20261119`**（本轮当前代码：`/lio/odom` 为 10 Hz、经 `odom_robo⁻¹` 换回 IMU 机体系、`poseFromSamples` 插值取相机位姿；本条跑批用 `visual_b_node`，注入门控 `app.visual_inject_max_dt` 只在 `visual_b_app` 单进程路径生效），**FL2/SL/A 取 `paper_sync`**（`lio.extrinsic.odom_robo` 回单位阵后的重跑）。
- move 序列：B 用 `move_ros2`（图像 header 保留主机时钟，以 `-p img_time_offset:=-204262818.9974` 覆盖）；原 `move_livoxclk`（图像 header 已改写为 Livox 时钟）副本已不在磁盘，FL2/SL/A 的 move 行仍来自 `paper_sync` 的该副本——两者只差图像 header 的时钟域，雷达/IMU 数据完全相同，对 LIO/轨迹无影响。
- rtk 用 RTK-SLAM 官方绝对评测（起点+前 30 s 定向，不做全轨迹对齐），同时给出 SE3 对齐 ATE 与 Gap；ntu 用 ATE（最近邻）与旋转区间 RPE。

## 0.5 关键结论

1. **move（小场景闭环）**：四臂路径 9.38–10.30 m、闭环 0.015–0.038 m、z 在 -0.03 ~ 1.00 m，几何一致；A/B 地图与 FL2 同量级。
2. **ntu（有真值室外）**：ATE FL2 0.03–0.04 m、SL 0.10–0.13 m、B 0.10–0.13 m、A 0.10–0.13 m；旋转区间 RPE RMS 0.08–3.25°（逐行见 §2）。
3. **room（无真值，仅几何自洽）**：路径 107.3–107.9 m、闭环 1.70–1.74 m；无 FL2 行（该 bag 的 `/livox/lidar` 为 PointCloud2，FL2 臂不支持）。
4. **rtk（长时 + 室内约 461 s 无 GNSS + 无回环优化）**：绝对 RMSE 0.4–0.6 m，主要来自室内累积漂移；官方基线（0.347–0.561 m）含离线优化，不可直接比绝对值。逐检查点分化见 §2。
5. **实时性**：每帧延时中位 26–378 ms；整段积压作废行：retail/FL2、retail/SL、retail/A、rtk/B（见 §3）。

> **rtk 数值口径注意事项（重要）**
> 1. 该序列 `/gnss/fix` 只在 t≈0–112 s 与 t≈573–599 s 有两个有效段，中间约 461 s 在室内、无任何有效定位；检查点覆盖整段，因此中后段误差是**纯里程计累积漂移**，不是定轨误差。
> 2. 本仓库链路只做在线 LIO（结束时导出 `odom_poses.txt` 关键帧供外部 SC-PGO），**未做回环/全局优化**；`eval_ref` 里官方基线（super_lio 0.347 m、visoff 0.348 m、fast_livo2 0.561 m）是离线/优化后轨迹，与本表不可直接比绝对值。四臂之间同口径，可横向比较。
> 3. 逐检查点看：室外段（t≈43/85 s）各臂都在 1–2 m 内；进入室内（t≥162 s）后各臂分化，该部分误差是「室内抗漂移/异常恢复」能力的排序，不反映室外定轨精度（逐检查点误差见 `node.log` 的 RTK 探针与 `/tmp/rtk_<arm>_imu.txt`）。
