# ============================================================
# 8. 已知坑（换环境大概率踩）
# ============================================================
# - WSL 127.0.0.1 UDP 单播不通（最坑）：ip rule 的 ipproto udp lookup 127 命中 table 127 里的
#   `127.0.0.1 via 169.254.73.152 dev loopback0`，单播被送进不通的 localhost 转发代理，表现为
#   `ros2 node list` 空、订阅端零数据、只有 SPDP 多播发包。修复（root）：
#   ip route del 127.0.0.1 via 169.254.73.152 dev loopback0 table 127
# - ros2 bag play 后台运行必须 --disable-keyboard-controls + < /dev/null，否则提前退出（实测只播 30s）
# - WSL/单机 DDS：ROS_LOCALHOST_ONLY=1 + FASTDDS_BUILTIN_TRANSPORTS=UDPv4 + 统一 ROS_DOMAIN_ID
# - 视觉节点落盘在 SIGINT 后 ~50s（彩色地图），别提前 pkill 掉；FL2 的 PCD 在
#   third_party/FAST-LIVO2-ROS2/Log/pcd/，SIGINT 后要等进程退完再拷（退出时可能 segfault，PCD 已完整落盘）
# - FL2 启动报 "Type support not from this implementation ... liblivox_ros_driver2__rosidl_typesupport_fastrtps_cpp.so"：
#   先 source $DOG_WS/install/setup.bash，再 source $FL2_WS/install/setup.bash（顺序不能反）
# - 编译务必 -DCMAKE_BUILD_TYPE=Release（Debug 着色慢一个数量级）
# - FAST-Calib：节点名 mono_qr_pattern vs yaml 顶层 fast_calib → 不加 -r __node:=fast_calib 会静默用默认参数；
#   bag 必须静止、整段累积；qr_params.yaml 的 bag_paths/image_paths 不能写成空列表 []
# - 时间基准：bag 消息 stamp 是设备时钟域（2000 年纪元），各传感器一致，不影响同步；但自采 move 的两版 bag
#   图像时钟不同——move_livoxclk 已改写为 Livox 时钟（A/B 用），move_ros2 保留主机时钟
#   （FL2 靠 img_time_offset: -204262818.9974 对齐）
# - 内参分两套：Retail_Street 用 1280x1024 全分辨率 fx=1293.56944 fy=1293.3155 cx=626.91359 cy=522.799224，
#   bag 实际 640x512，靠 scale=0.5（FAST-LIVO2 系）/scale=2.0（Point-line 系）折算；
#   自采数据（MV-CB013，1280x1024 原图）：fx=708.631259 fy=708.715136 cx=644.493727 cy=495.883592，
#   k1=0.05446642 k2=-0.04514737 p1=8.546e-06 p2=1.0487e-03，见 $REPO/config/camera_intrinsic.yaml
# - 官方 FAST-LIVO2 的 parameter_blackboard 在部分环境不可达：用 07a_wrap_official_cfg.py 把内参并入主参数文件
# - move bag 本身有图像空洞：/left_camera/image 缺 14.87–17.51 s（2.63 s）与 70.47–71.20 s（0.73 s），
#   imu/lidar 连续；FL2 在该窗口尾部出现 0.59 m 瞬态跳变（A/B 无），排查中
