## 0. 结论摘要

1. **sl 与 e1 不是同一批原始 LiDAR/IMU 扫描**：两个独立 bag，帧数（40 vs 213）、帧率（~0.55s/帧 vs ~0.11s/帧）不同；仅 header 时间戳处于同一时钟域且窗口重叠（可插值，但不可逐扫描对应）。
2. **逐帧去畸变后的 body 系点云已保存**（bag 的 `colored_cloud` topic，几何即无色部分），但现有实验没有统一使用它——sl 侧是从世界系 CSV pool 反推 body 坐标。
3. **位姿替换只替换世界位姿 `(R,t)`，不重做逐点运动补偿**；去畸变已固化在 body 云中，且与各自原始轨迹耦合 → 现有实验无法真正分离「帧内去畸变」与「帧间世界位姿」。
4. **伪 GT 的 LOO 只排除目标帧自身，不排除邻近帧**，与 handover §4.B 要求不符。
5. **「17.40 cm/点」= `consistency_cost` 的 `cost_per_pt_cm`**（25cm 体素 LOO 稳健残差均值，硬截断 0.4m），受 25cm 粗体素量化与「点-质心」退化项主导，**不是干净的帧间位姿误差**；对照 1cm 体素 `plane_rms` 仅 0.47cm。
6. **伪 GT 精化位移极小**（vs sl 平均 0.38cm，仅 2 次迭代），consistency 17.40→17.34cm 几乎不变；**退化方向/可观测性未计算**。不能据此认定 sl 轨迹已达几何最优。

**总体判定：现有数据与脚本不满足 handover §三 的无色几何交叉实验条件**，需从原始 bag 重放、统一帧采样与时间戳、补存 body 云后重做。

## 2. 六个问题的回答

### Q1：sl 和 e1 是否同一批原始 LiDAR/IMU 数据？能否按扫描时间戳一一对应？

**否，不是同一批原始扫描。**

已核实（直接读两个 bag 的消息头时间戳）：

| | sl_frames | e1_frames |
|---|---|---|
| colored_cloud 帧数 | 40 | 213 |
| odom 条数 | 219 | 243 |
| header 时间窗 | 946685508.70 → 946685530.70（≈21.9s） | 946685507.99 → 946685531.70（≈23.7s） |
| 帧率 | ≈0.55 s/帧 | ≈0.11 s/帧 |

- header 时间戳（`m.header.stamp.sec + nanosec*1e-9`）确实处于**同一时钟域**（都约 946685xxx 秒），窗口重叠。实测 sl 的 40 帧 header 时刻全部落在 e1 odom 时间窗内（40/40），因此 `make_interpolator` 在 sl 帧时刻对 e1 位姿做插值是**有效插值而非边界截断**。
- 但**帧数、帧率、时长都不同**，且两 bag 的 ROS 录制墙钟相差约 13 小时（`messages.timestamp` 列 1794157… vs 1794203…）。没有任何 scan 级一一对应关系被保存。

结论：`pose_source_factorial.py` 里的「e1 位姿」是 **sl 的 body 点云 + e1 的轨迹（在 sl 帧时刻插值）** 的混合体；「e1 几何」是 e1 自己采样的 40 帧（`np.linspace` 均匀抽取）。二者**不是同一扫描的不同位姿**，交叉矩阵的「同源扫描」前提不成立。

### Q2：是否保存了逐帧去畸变后、尚未转世界系的 body 系无色点云？

**是。** bag 的 `colored_cloud` topic 就是逐帧、已去畸变、仍在 LiDAR（body/imu）系的点云，几何 xyz 即无色部分。

依据 [visual_a_node.cpp](file:///\\wsl.localhost\Ubuntu-22.04\home\ywj\git\Super-LIVO\solution_a_lightweight\super_livo_visual_a\src\node\visual_a_node.cpp#L581-L584)：
- `points_lidar` 来自 `lio/cloud_body_dense`，「已由 Super-LIO 的 DenseThread 逐点去畸变到扫描结束时刻」；
- `point_stamps` 全部等于 `body_stamp_`，「点云已去畸变，无需再做逐点补偿」；
- 发布时 `msg.header.frame_id = "imu"`（[L796-L821](file:///\\wsl.localhost\Ubuntu-22.04\home\ywj\git\Super-LIVO\solution_a_lightweight\super_livo_visual_a\src\node\visual_a_node.cpp#L796-L821)），点仍在 LiDAR 系。

对应到离线脚本 [blackframe_voxel_replay.py](file:///\\wsl.localhost\Ubuntu-22.04\home\ywj\git\Super-LIVO\tools\blackframe_voxel_replay.py#L225-L227) 的 `Pw = Pb @ R.T + tv`，`Pb` 即该 body 系云。

**但存在不一致**：`pose_source_factorial.py` 的 sl 侧（`main`）并未直接读 bag 的 body 云，而是用 CSV pool（世界坐标）反推 body 坐标（[L428-L434](file:///\\wsl.localhost\Ubuntu-22.04\home\ywj\git\Super-LIVO\tools\pose_source_factorial.py#L428-L434) `Pb_pool = (P0 - tv) @ R`），正是 handover 明确禁止的「用世界系反推 body 系」。e1 侧（`e1_side_experiment`）才直接读 bag body 云。两套几何来源不一致。

### Q3：位姿替换替换的是世界位姿，还是同时替换逐点运动补偿？

**只替换世界位姿 `(R,t)`，不重做逐点运动补偿（去畸变）。**

所有组合统一 `Pw = Pb @ R.T + tv`，`Pb`（body 云）固定不变。而 `Pb` 的去畸变是 Super-LIO 用**该次运行自己的轨迹/IMU** 完成的，已固化在点里。

这意味着：`sl 几何 × e1 位姿` 得到的是「sl 的去畸变结果 + e1 的世界位姿」，是一个**物理上不自洽的混合体**——去畸变补偿量来自 sl 轨迹，却套在 e1 轨迹上。因此 handover §三 想分离的「帧内去畸变几何」与「帧间世界位姿」**用「只换世界位姿」无法真正分离**。

要真正分离，需要 Super-LIO 额外输出「未去畸变的原始点 + 逐点时间戳」，再用统一轨迹重新去畸变；现有 body 云无法满足。

### Q4：伪 GT 的 LOO 地图是否排除了目标帧及其邻近帧？

**只排除了目标帧自身，未排除邻近帧。**

[pose_source_factorial.py L78-L94](file:///\\wsl.localhost\Ubuntu-22.04\home\ywj\git\Super-LIVO\tools\pose_source_factorial.py#L78-L94) `_loo_frame_params`：对帧 `i` 只做 `n_o = n_all - cnt[:,i]`、`s_o = s_all - sm[:,i]`、`SS_o = SS_all - SS[:,i]`，即 leave-one-out 单帧扣除，**不扣除时间上相邻的帧**。

这与 handover §4.B「不包含测试帧及其邻近帧」的要求不符。邻近帧与目标帧空间高度重叠，会显著高估评估结果（handover §四.B 已预警此问题）。

此外，建图体素 `edge=0.25`（25cm），远粗于着色体素 1cm，进一步降低该几何评估的分辨率。

### Q5：「17.40 cm/点」究竟是什么指标？

已核实：`17.40 cm/点` = `consistency_cost(...)["cost_per_pt_cm"]`，实测 `sl = 17.3996…`。

**定义**（[pose_source_factorial.py L208-L228](file:///\\wsl.localhost\Ubuntu-22.04\home\ywj\git\Super-LIVO\tools\pose_source_factorial.py#L208-L228)）：
- 用全部帧在 **25cm 体素**上建图，对目标帧做 LOO（单帧扣除）得到平面/线/点分类。
- 每个落入有效体素（LOO 后其他帧点数 ≥4）的点，按体素类别算残差：
  - 平面：`|n·(P - mu)|`（点到平面距离）
  - 线：`‖Uᵀ·(P - mu)‖`（点到线距离）
  - 点（退化为既不平面也非线）：`‖P - mu‖`（**点到体素质心距离**）
- 残差硬截断 `min(r, 0.4)`，求和后除以覆盖点数，×100 得 cm/pt。
- `cov_frac = 98.07%`（覆盖率）。

**关键混淆（该指标不能当作帧间位姿误差）**：
1. **25cm 粗体素量化**：质心 `mu` 是 25cm 体素内其他帧点的均值，平面拟合在一块 25cm 大面元上进行；曲面/多面/边缘落入同一体素时，单平面残差会被体素离散主导。
2. **退化体素的「点-质心」项**：`‖P - mu‖` 是纯体素内散布，与帧间位姿无关，却混入均值。
3. **硬截断 0.4m + 只报均值**：无 P50/P90/P95，无逐帧分解，无法看分布。

**对照**：1cm 体素的 `geo_metrics.plane_rms` 实测仅 **0.47cm**（`sl_clean`），`spread_med_cm` 仅 0.67cm。17.4cm 与 0.47cm 的量级鸿沟，直接说明 17.4cm 主要来自 25cm 体素离散与点质心项，**不是 sl 存在 17cm 几何误差的证据**。

### Q6：伪 GT 优化前后，客观几何残差、可观测性、轨迹变化分别是什么？

**有记录的（已核实）**：
- 几何残差：`consistency` sl = 17.40 cm/pt → refined = **17.34 cm/pt**（几乎不变）。
- 轨迹变化：`pose_dev_vs_sl["refined"]["dev_vs_sl_mean_cm"] = 0.377cm`，`pairwise_trans_cm = 0.666cm`（vs e1 的 11.48cm / 2.92cm）。
- 迭代：`refine_hist` 仅 **2 次迭代**（iter0 cost 145288 → iter1 145124）即触发收敛退出。

**缺失的（未实现）**：
- **退化方向 / 可观测性完全未计算**：无 Hessian 特征值、条件数、退化轴分析（`refine_poses` 内部虽算了 H，但未输出其谱）。
- 无逐帧残差/修正量的时间序列，无残差空间分布。

**风险（与 handover 预警一致）**：
- 优化器对 frame0 锚定（`if i == 0: continue`），每帧单次修正被硬限幅 `clip_t=0.05m`、`clip_r=0.02rad`，且仅 2 次迭代即停 → 「位移很小」更可能是**约束不足/局部极小/信息泄漏**，而非原始轨迹已达最优。
- LOO 不排邻近帧 → 参考地图信息泄漏。
- body 云去畸变与轨迹耦合 → 即使真精化到局部极小，也不能代表真实几何最优。

## 3. 无色几何交叉实验可行性判定

**不满足。** 具体缺口：

| handover §三 要求 | 现状 |
|---|---|
| sl/e1 同一批原始扫描、可逐时间戳对应 | 不满足：40 vs 213 帧、帧率不同、无 scan 对应 |
| 逐帧去畸变 body 系无色点云已保存 | 部分满足：body 云在 bag 内，但 sl 侧脚本用世界系反推，未统一使用 |
| 只替换世界位姿、帧内几何/位姿可分离 | 不满足：去畸变固化在 body 云且与各自轨迹耦合，无法分离 |
| 统一时间戳、统一空间范围、统一评价 | 部分满足：时间窗重叠，但帧采样（sl 前 40 帧 vs e1 `linspace` 抽 40 帧）不一致 |

**建议**（若要继续交叉验证）：
1. 从原始 bag 重放，统一帧采样网格（例如按同一帧率抽取同一时间窗），补存逐帧 body 云与逐帧轨迹；
2. sl 侧改回直接读 bag body 云（放弃「世界系反推 body」路径）；
3. 若目标是分离「帧内去畸变 vs 帧间位姿」，需 Super-LIO 输出「未去畸变原始点 + 逐点时间戳」，用统一轨迹重新去畸变，否则只能评估「去畸变+位姿」的联合效应。

## 4. 指标「17.40 cm/点」与几何评估的补充事实

- `consistency_cost` 的三源一致性（已核实）：sl 17.40 / e1 17.33 / refined 17.34 cm/pt，三者几乎相同——说明该指标对这三条轨迹的差异**不敏感**，进一步支持「17.40 主要由体素离散/点质心项主导，而非位姿差异」。
- `geo_metrics`（1cm 体素、与位姿无关的体素内指标）各 L 级几乎不变（`plane_rms` 0.43–0.49cm，`spread_med` 0.66–0.67cm），而 `collide_frac` 随位姿扰动单调下降（0.106 → 0.005）——说明当前无色几何指标里，**真正随位姿误差变化的是「多帧碰撞率」这类体素归属指标，而非平面残差**。

## 5. 风险与缺口清单

1. `pose_source_factorial.py` sl 侧用「世界系 CSV pool 反推 body 坐标」（违反 handover 反推禁令）。
2. LOO 不排邻近帧（Q4）。
3. `consistency_cost` 用 25cm 体素 + 点质心退化项，混入大量与位姿无关的项（Q5）。
4. 伪 GT 精化无退化方向/可观测性分析，且 frame0 锚定 + 硬限幅 + 2 迭代，存在约束不足风险（Q6）。
5. 三源 consistency（17.40/17.33/17.34）几乎无差异，该指标对轨迹差异不敏感，不能用作位姿误差判据。
6. sl/e1 帧采样方式不一致（sl 前 40 帧 vs e1 均匀 40 帧），交叉对比存在混杂。

## 6. 已证实结论 vs 待验证假设

**已证实（代码 + 数据核实）**：
- sl/e1 非同源扫描、不可逐时间戳对应（Q1）。
- body 系去畸变云已保存，但 sl 侧脚本未统一使用（Q2）。
- 位姿替换仅换世界位姿、不重做去畸变（Q3）。
- LOO 仅排除目标帧自身（Q4）。
- 17.40 cm/pt 的公式与覆盖率，及其 25cm 体素/点质心混淆（Q5）。
- 伪 GT 位移极小、仅 2 迭代、无退化分析（Q6）。

**待验证（本报告未下结论）**：
- Super-LIO 无色点云是否真的存在帧内几何误差或帧间几何发散——**当前任何数据与指标都不足以回答**，需按 §3 补数据后重做。
- e1 的高椒盐率（18.8%）与 sl（5.0%）差异的来源——现有实验无法区分「几何」「观测集内容」「质量门控」「时间配对」。
